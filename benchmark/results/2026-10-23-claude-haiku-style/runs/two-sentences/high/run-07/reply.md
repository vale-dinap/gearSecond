Rust's borrow checker rejects two simultaneous `&mut` references to the same value because aliased mutable access lets one path change data out from under another, so the compiler enforces that a mutable borrow is exclusive while it is live. This prevents data races and iterator invalidation bugs, such as a `Vec` being reallocated while a reference into its old buffer is still in use, which would otherwise cause use-after-free or undefined behavior.
